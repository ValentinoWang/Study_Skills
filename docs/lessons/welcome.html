Interactive Demo

这是一节会“等你思考”的网页课。

它不是为了展示复杂前端，而是验证最重要的主动学习交互：术语按需展开、提示分级开放、答案自己先写、进度在浏览器本地保存。

1. 一个核心术语

什么是 GitHub Pages？

直觉：把 GitHub 仓库里的静态网页文件直接变成一个可以访问的网站。

严格一点：它是 GitHub 提供的静态站点托管能力，适合 HTML、CSS、JavaScript 这类不需要常驻后端进程的内容。

比喻：仓库像书库，Pages 像自动把其中一个文件夹摆到橱窗里。

边界：它不是一台长期运行的虚拟机，所以不能直接承载数据库或常驻 Python/Node 服务。

2. 把它当成一道题

假设你有 100 份由 AI 生成的单文件 HTML 学习材料，希望低成本分享给别人，而且不需要登录和数据库。你会优先选择“虚拟机”还是“静态托管”？为什么？

3. 逐级看提示

Hint 1 · 先看需求性质
这些页面是否需要服务器持续执行代码，还是浏览器拿到文件以后自己就能运行？
Hint 2 · 再看运维成本
如果只是 HTML/CSS/JS，虚拟机意味着你还要维护系统、Web Server、端口和服务状态。
Hint 3 · 接近答案
优先选择 GitHub Pages 这类静态托管；只有真正出现后端状态或服务端计算时，再升级到服务器。

4. 反思

真正应该记住的不是“GitHub Pages 这个产品名”，而是：先判断问题到底需要静态托管还是常驻计算资源。
