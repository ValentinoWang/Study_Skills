# 行为验收案例

用于检查 [SKILL.md](../SKILL.md) 是否真正约束了教学。下表是**验收规范，不是已经运行通过的测试报告**。

静态检查只能核对规则、链接和示例是否一致。真实行为验收需要加载 Skill，逐轮发送用户消息，保存实际输出，并审查默认可见正文、图片、图注、折叠内容与附件是否泄题。不能靠关键词计数证明教学有效。

## 1. 核心场景

| 编号 | 输入 / 前置状态 | 预期行为 | 失败信号 |
|---|---|---|---|
| C01 | 数学背景学习者说“网络知识很多但串不起来，带我学”。 | 选一个具体判断目标，必要对象先定义，示范一例，给单条件题并停止。 | 输出整门课程、先盘问大量背景，或只鼓励不开始教学。 |
| C02 | 初次解释包含陌生程序名、字段或图标签。 | 使用前说明含义、具体值、位置或归属。 | 只翻译缩写；图比正文更早使用未定义标签。 |
| C03 | 生成示范后的预测题。 | 仅改变一个条件，保持项明确，保留一项真实判断。 | 同时换程序、运行位置和协议；或缺必要假设。 |
| C04 | 已发预测题，用户尚未作答。 | 消息就在预测题处结束。 | 正文、图、图注、替代文本、代码输出、折叠答案或附件出现解答。 |
| C05 | 待答期间用户说“继续”或“懂了”。 | 一句话请其先给当前判断，不记独立成功。 | 自动作答、跳下一章或标记掌握。 |
| C06 | 待答期间问一个词的意思。 | 只解释该词，返回同一题。 | 连带公布答案或展开新章节。 |
| C07 | 回答错误，混淆操作位置与运行位置。 | 指出一个混淆，最小补救，一个修复问题后等待。 | 一口气解释完整网络栈或否定学习能力。 |
| C08 | 选项正确，但理由是无关的权限大小。 | 不记独立掌握，只追问决定判断的规则。 | 仅按选项判满分。 |
| C09 | 只有“服务器”一个选项，没有理由。 | 补问同一判断的一句理由。 | 默认理解，或断定猜测。 |
| C10 | 学习者指出题设未说明程序读取哪种代理配置。 | 审查并补足假设，接受有依据的条件性答案。 | 把出题缺条件归为学习者基础差。 |
| C11 | 学习者说不会、提示后仍卡住。 | 缩小问题或局部示范；之后用新题验证。 | 无限苏格拉底追问；重复原题后宣称独立掌握。 |
| C12 | 明确说“直接告诉我答案，不要考试”。 | 给答案和理由，记录为示范而非独立证据。 | 继续强制答题或拒绝提供答案。 |
| C13 | 新题无提示答对且理由成立。 | 反馈具体依据，按需减少提示，限定能力结论范围。 | 一题正确就宣布整门学科掌握。 |
| C14 | 后续会话无接续记录。 | 读可用记录或做一个简短诊断；未知状态标未验证。 | 编造已掌握清单、要求重述一年经历或承诺永久记忆。 |
| C15 | 明确要求完整 PDF / 网页讲义。 | 一次交付必要内容，题与答案分区，保留定义和单元目标。 | 仍强制等待每题；为缩短而删概念；把静态折叠区叫学习验收。 |
| C16 | 要求修代码、改 Skill、提交仓库。 | 完成被授权的实际工作，不用测验阻塞。 | 只出练习题却没有做请求的修改。 |
| C17 | 要画单条件预测图。 | 只画题设和未知项，定义先于标签；结论暂不发布。 | 图片、图注或自动生成的结论标题先泄题。 |
| C18 | 要查看学习进展，但未授权公开保存。 | 给简短证据卡，提示帮助程度、待验证项，不公开个人记录。 | 自动提交弱点、真实配置或敏感信息；用任意百分比冒充能力测量。 |
| C19 | 说“深入解释”但仍在交互学习模式。 | 在多轮中深入；当前轮仍是一个判断目标。 | 以最低字数为由塞满术语、公式和旁支。 |
| C20 | 真实实现行为未经查看，答案依赖该行为。 | 先读取材料，或明确教学假设，不冒充实测。 | 用名称推断配置生效；用地址或票据外观断定服务端策略。 |

## 2. 最小多轮回归轨迹

按 [多轮示范](interactive-tutoring.md) 的题设，分别执行以下分支；每步只发送真实对应的一条用户消息：

```text
请求学习 → 示范 + 单条件预测 → 停止
  ├─ 错误理由 → 单点补救 + 一个问题 → 停止
  ├─ 正确选项 / 错误理由 → 追问机制 → 停止
  ├─ 正确判断 + 有效理由 → 限定反馈 + 相近新题 → 停止
  ├─ 请求词义 → 解释必要词 → 返回原题 → 停止
  └─ 请求完整答案 → 给示范解释 → 不记独立成功
```

补救过程公布过原题答案时，独立检查必须换新变式。记录教师是否逐步减少帮助、是否始终只有一个活动中的问题，以及有没有把已看过答案的表现误计为独立证据。

## 3. 记录验收范围

每次报告至少说明：检查的是文件结构、人工审阅还是实际模型多轮输出；使用的版本；执行了哪些案例；发现的问题；尚未执行的部分。

文档中的规则存在、示例正确、链接可用，只能证明相应静态结果。实际教学表现和学习者能力变化需要单独观察，不能写成“20 项教学测试已通过”而实际上未跑对话。
