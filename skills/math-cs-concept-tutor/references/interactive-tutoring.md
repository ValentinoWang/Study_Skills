# 多轮示范与接续模板

本文件供教师备课，不应整段发给正在答题的学习者。行为规则以 [SKILL.md](../SKILL.md) 为准。下列是假设明确的教学例子，不是对任何真实设备配置的诊断。

## 1. 先写一个可检验目标

不要用“理解代理 / 学会网络”作为单元完成标准。改成：

> 给定程序实际运行的位置，能判断哪台机器上的程序配置可能影响这次请求，并说明理由。

本轮不用讲地址分类、加密格式、商业代理报价和服务端策略。它们不是完成这个判断的必要前置。

教师备课表：

| 项目 | 本例内容 |
|---|---|
| 必要对象 | 两台独立机器；下载程序 P；各机器上 P 的代理设置；代理服务。 |
| 题设 | P 启动时只读取所在机器上自己的设置；设置不自动同步；不考虑额外转发。 |
| 基准例子 | P 在电脑运行，读取电脑上的设置。 |
| 唯一改变量 | 下一次 P 改在云服务器运行。 |
| 保持项 | 下载目标、程序读取设置的规则、两台机器各自的配置内容均不变。 |
| 独立证据 | 正确判断，并以“实际运行位置决定本题读取哪份设置”为理由。 |
| 停点 | 给出预测题后等待，不附答案图。 |

## 2. 首轮：示范后提问，然后停止

下面这个框内是可以发给学习者的一轮内容：

> **这轮只判断：哪台机器上的设置会影响正在下载的程序。**
>
> 先认四个对象。你的电脑和云服务器是两台独立运行程序的机器；P 是下载文件的程序代号；代理服务替 P 转发连接；P 的代理设置告诉它是否使用代理、使用哪一个。
>
> 为了只研究一个问题，本例规定：P 启动时只读取它所在机器上的那份设置；两台机器的设置不自动同步，也没有额外转发规则。
>
> **先看示范。**P 在电脑上运行。电脑里的设置写着“使用代理 A”。因此这次 P 读取电脑上的设置，通过代理 A 下载。云服务器上的设置没有被这次 P 读取。
>
> **现在只改变程序运行位置。**下一次把 P 放到云服务器运行。下载目标、读取设置的规则、两台机器各自的设置都不变。
>
> 这次下载读取的是电脑上的设置，还是云服务器上的设置？请先给一个判断和一句理由。

此处结束消息。不要再附“关键是程序在哪”“因此应改服务器”等已经解决该题的总结。

本例是教题，不是实测；真实程序未必读取系统代理，需另查程序文档或实际配置。这个边界写在题设中，不在答错后突然引入。

## 3. 后续分支：一次只走符合真实回答的一支

### 3.1 判断错：把操作位置当成运行位置

学习者：“电脑。我是在电脑上操作服务器的。”

教师可以回复：

> 你指出了操作从电脑发起。这里还要把“从哪里操作”和“程序在哪里运行”分开；本例规定 P 读取运行处的设置。先只确认一件事：变式中的 P 现在实际运行在哪台机器上？

然后停止。不要附加远程登录协议、网络地址转换、虚拟网卡等知识。这是提示后的修复，不是独立掌握证据。

### 3.2 判断对，理由不对

学习者：“服务器，因为服务器的权限更大。”

教师可以回复：

> “服务器”这个判断与题设一致，但题目没有用权限大小决定读取哪份设置。你能指出题设中真正决定读取位置的那条规则吗？

然后停止。不要把正确选项与错误理由一并夸成“完全掌握”。

### 3.3 只有选项，没有理由

学习者：“服务器。”

教师只追问与同一判断有关的一句理由，不立即给下一章，也不默认是猜对或真会。

### 3.4 题设不清，条件性答案合理

学习者：“如果 P 不读系统代理，改系统设置可能没用。”

教师先承认这是有效边界，再明确本题说的是 P 自己读取的配置，不是所有程序通用的系统设置。若原题没有交代读取规则，应修正题设，不扣给学习者。

### 3.5 说不会或要答案

先给一个局部提示；若仍然卡住，可完整示范“P 在哪里 → 读取哪里的设置”。明确要求答案时直接解释，不强迫反复尝试。

记录为看过示范或在提示下完成。不要原封不动再问原题并据此算作独立成功。

### 3.6 真正独立答对

学习者：“服务器。因为 P 现在在那里执行，并且题设说它只读取所在机器的配置；从哪里点按钮不是这条规则的条件。”

教师反馈应点明其有效推理，再选择一个少提示的新检查，例如：

> 你把操作位置和运行位置分开了，理由也用到了题设。下一题里 P 仍在云服务器运行，只把远程操作设备从电脑换成手机，其他条件不变。P 读取的那份设置会不会因此改变？请给判断和一句理由。

提问后再次停止。这验证相近变式，不是宣布已经掌握整个代理配置。

## 4. 帮助如何减少

不要每个新变式都重新展示完整答案步骤。按实际表现调整：

| 阶段 | 教师提供 | 留给学习者 |
|---|---|---|
| 示范 | 对象、条件、完整轨迹与理由。 | 跟随并澄清不认识的对象。 |
| 初次预测 | 对象与完整题设，指出唯一改变量。 | 预测及理由。 |
| 相近新题 | 题设与必要定义，不给轨迹。 | 自己选相关规则。 |
| 后续复查 | 简短场景，不重贴答案。 | 回忆、判断并说明证据。 |

提示只解决当前最小障碍；可以从“圈出执行者”升级到“补出一步轨迹”，再到完整局部示范。每次给一级，不一次把三层提示全摊开。具体表现不支持撤掉提示时，保留帮助并缩小目标。

## 5. 用一张接续卡串起来

下面是空模板，不是对某个用户已经掌握的声明：

```text
当前判断目标：
已解释的必要对象：
独立证据：题目条件 + 用户理由；没有则写“尚未验证”
已给帮助 / 待核混淆：
停点与待答题：
下一次最小检查：
```

“说懂了”“复制了配置”“跟着教师答出原题”不能填作独立证据。若使用简写，接续时先解释简写；不以任意百分比表示掌握。

两种记录示例：

- “已看完整示范；提示后识别出程序在服务器运行；相近无提示变式尚待回答。”
- “在执行位置变化与操作设备变化两个明确条件下，均给出无提示判断和有效理由；真实程序的配置读取行为尚未实测。”

这是可分享的教学状态，不包含秘密推理、真实账号、票据或私人网络信息。用户未授权时不把接续卡写入仓库，也不承诺系统会永久记住。

## 6. 完整文档不是实时对话

明确请求讲义时保留概念解释、示范、变式、提示与答案，但把答案置于独立区域；答案区解释为何成立、在哪些题设下成立。

静态页面的折叠答案只是阅读控制，不是掌握检测。完整讲义交付成功、页面检查通过，不等于学习者独立答题成功。
