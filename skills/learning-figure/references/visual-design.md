# 教程视觉设计：让读者先看见要理解的关系

## 视觉语法

一张图围绕一个可回答的问题；图题说问题，图下注明结论和适用边界。
先选择信息结构，再决定图型。删除仅重复正文、只有彩色框却没有关系增量的图。

| 要解释的内容 | 视觉重点 | 常见误用 |
|---|---|---|
| 请求、验证、写入、响应 | 时间方向、参与者、失败/成功分支 | 用普通箭头串联框，遗漏并发和原子边界 |
| 修改前与修改后 | 同一行、同尺度、变化字段 | 左右字段顺序不同，使读者来回寻找 |
| 归属与权限 | 容器边界、拥有者、跨界行为 | 用距离近暗示包含关系 |
| 损失/误差随迭代变化 | 坐标轴、起点/过程/终点、线型 | 把迭代次数直接写成速度提升 |
| 算法耗时/类别对比 | 共同尺度、单位、基线 | 柱状图截断零点、用面积制造差异 |
| 测量关系与噪声 | 原始点、样本量、估计与观测区别 | 只画拟合曲线或隐去不利点 |

## 样式与层级

采用浅背景、深正文、轻边界和少量语义强调。标题、读图提示、图主体、结论、来源分层，
不要把它们全部塞进 SVG。避免渐变背景、厚阴影、装饰 3D、过度圆角和彩虹色块。
一组比较保持同尺度、同顺序、同字形；颜色含义不能在一张图内变化。

可执行数据图样式唯一源为 `assets/chart.css`。机制图阈值仍由 `profiles/readable-v2.json` 管理，
不要新增一组互相矛盾的几何数字。新数据图用 16px 正文、20–24px 图题、局部滚动与明确键盘焦点。
绘图文字至少按真实展示宽度检查；不能把论文常见的物理字号直接搬到网页后缩成小字。

用颜色 + 点形/线型/文字表达系列差异；灰度检查只是一项检查，不等于完整无障碍证明。
原则是：先留白和对齐，再突出一个重点；不是先加更多颜色。

## 对科学绘图能力的取舍

吸收 `scientific-visualization` 的诚实编码、数据溯源、作用域样式和输出验收；
不照搬期刊毫米尺寸、多面板密排、投稿 DPI 或依赖在线模型的整页生图。
自然语言生图仅可作为非定量概念草稿，不能作为数值曲线、精确拓扑、公式或算法连接关系的事实来源。

## 修图顺序

发现拥挤时依次：调整结构分组 → 换行/扩大节点 → 减少一图承担的问题 → 拆分图。
不能删掉必要事实，不能靠缩字、透明文字或裁切修复。

验收时分别回答：文字是否能读、关系是否正确、视觉重点是否符合学习问题。
自动几何/截图只提供证据，不直接得出“好看”或“已讲懂”的结论。
