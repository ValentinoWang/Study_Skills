Deep Dive 06 · 约 12–16 分钟

深挖六：AI Coding 时代，真正的交付链不是“代码写完 → push”

0. 本节先认词 / 先认变量

词或变量中文直觉例子
Source Code · 源码开发者真正编写和维护的代码。仓库里的前端、后端、配置。
CommitGit 中一版固定历史快照。某次修改对应一个 commit SHA。
Build · 构建把源码变成可运行或可发布产物。生成前端静态文件、Docker image。
Artifact · 构建产物真正准备部署的输出。镜像、二进制、静态站点包。
artifact_digest构建产物的内容指纹。证明“部署的是不是刚才验收的同一份字节”。
Release Candidate · 发布候选已经冻结、准备进入最终验收/发布的一版明确对象。绑定源码 commit、artifact digest、测试结果。
CIContinuous Integration，持续集成。代码变化后自动 build、test、lint。
CDContinuous Delivery / Deployment，持续交付 / 持续部署。把合格候选推进到可发布或生产环境。
Deployment · 部署把某个明确产物放进目标运行环境。把 image digest 部署到生产。
Readback · 读回部署以后从真实环境重新读取版本/页面/接口，确认真的生效。线上 API 返回当前 build SHA。
Observability · 可观测性通过日志、指标、追踪推断系统内部状态。错误率、P95 延迟、request trace。
Rollback · 回滚把运行版本恢复到之前的已知安全状态。切回上一个 image digest。

1. Git 证明“源码历史”，不证明“线上版本”

Commit 只能证明某一版源码存在。main 指向最新 commit，也不能推出生产服务器已经运行它。

至少要区分三个身份：

  • source_commit：源码是哪一版。
  • artifact_digest：构建出的产物是哪一份。
  • running_version：线上当前到底运行哪一版。

这三个变量最好能互相追溯。

2. 测试分层：每种测试证明的东西不同

测试先翻译擅长证明
Unit Test单元测试函数、小算法、小状态转换
Integration Test集成测试数据库、服务、组件之间能否正确协作
Smoke Test冒烟测试系统最关键入口是不是基本活着
E2EEnd-to-End，端到端测试从用户入口穿过多个组件的完整链路
UATUser Acceptance Testing，用户验收测试真实业务场景是否满足使用目标

所以“Mock API 下 E2E 全绿”只证明：在假后端返回可控数据时，前端链路能工作。它不能单独证明真实鉴权、真实数据库、支付平台和生产配置正确。

3. Release Candidate 为什么必须冻结

先定义下面几个变量：

  • source_commit：候选对应的 Git commit。
  • artifact_digest：候选构建产物的指纹。
  • migration_version：数据库结构迁移到哪一版。
  • configuration_version：运行配置是哪一版。
  • verification_report：这版已经跑过哪些检查及结果。
  • known_risks：已知但仍接受的风险。
release_candidate = {
  source_commit,
  artifact_digest,
  migration_version,
  configuration_version,
  verification_report,
  known_risks
}

这段伪代码只是在表达：验收对象必须是一个有明确身份的组合，而不是“最新代码”这种不断变化的概念。

4. CI/CD 是把重复动作变成机器合同

CI 负责在代码变化后统一执行 build、test、lint、type check 等。Continuous Delivery 的目标是“合格候选随时可发布”；Continuous Deployment 再进一步，把生产发布也自动执行。

高风险系统可以保留人工 Acceptance（验收接受）门，但这不妨碍构建、测试、部署准备都自动化。

5. Deployment Readback：真正去线上看一眼

部署命令返回成功只说明“部署工具认为操作完成”。你还应从真实目标环境读回：

  • 页面上是否出现新版本标识。
  • API 是否返回预期 build SHA。
  • 关键接口是否真的能工作。
  • 数据库 migration 是否处于目标版本。

Readback 是把“我执行过发布命令”升级成“我有证据证明目标环境真的变成了这版”。

6. Observability：Logs、Metrics、Traces 分别是什么

  • Logs · 日志：某一时刻发生了什么事件。
  • Metrics · 指标：错误率、请求量、P95/P99 延迟等连续数值。
  • Traces · 链路追踪：把一次请求经过的多个服务串起来。

P95 的意思是“95% 的请求延迟不超过这个值”；P99 类似，只是看更尾部的慢请求。

7. Rollback 为什么也不是万能药

代码版本可以切回去，但已经发生的支付、通知、邮件、数据库不可逆迁移不一定能自动撤销。这类外部副作用可能需要 Compensation · 补偿动作，例如单独发退款，而不是假装旧代码重新上线就把钱退回来了。

AI Coding 的合理分工：Agent 做大量可重复检查；人负责确认需求、不变量、高风险权限/资金边界，以及对一个明确 Release Candidate 作最终 Acceptance。
练习：Agent 说“200 个测试通过、build 成功、已经 push main”。为什么还不能说“线上验收完成”？

答案：还缺明确候选身份、真实后端/目标 Runtime 证据、数据库迁移状态、部署 artifact 身份、线上 readback、关键负向测试，以及有权主体的 Acceptance。
