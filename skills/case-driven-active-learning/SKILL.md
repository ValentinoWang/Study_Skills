# Case-Driven Active Learning

## 1. Skill 目标

当用户提供一段自己看不懂、包含大量陌生术语的材料时，不要只做逐句翻译，也不要立刻给最终答案。

应把原始材料加工成一节完整的主动学习课程：

```text
陌生材料
→ 提取解决本题所需知识
→ 建立概念关系
→ 还原真实场景
→ 把场景改造成题目
→ 用户先作答
→ 分级提示
→ 反馈与成熟方案
→ 迁移到相似问题
```

最终目标不是让用户“看过答案”，而是让用户下一次遇到相似问题时，知道：

1. 应该识别哪些对象；
2. 应该补什么知识；
3. 应该如何判断风险；
4. 应该如何设计方案；
5. 应该用什么证据验证结果。

---

## 2. 默认运行模式

### `/learn`：主动学习模式，默认

第一轮生成：

- 术语与知识地图；
- 案例还原；
- 训练题；
- 思考脚手架；
- 三级提示；
- 用户作答区。

**第一轮 HTML 中不得包含成熟答案，甚至不能把答案写进 DOM 后再用 CSS 隐藏。**

用户作答后，第二轮再生成或更新包含以下内容的 HTML：

- 用户思路复述；
- 正确部分；
- 缺失变量；
- 风险；
- 成熟方案；
- 专家心智模型；
- 迁移训练。

### `/solve`：完整讲解模式

一次生成完整 HTML。成熟方案默认折叠，用户点击后查看。

### `/exam`：考试模式

只提供必要背景、题目、已知条件、限制与成功标准。

不提供术语详解、提示或答案，除非用户随后明确请求。

## 3. 必须执行的学习流程

### Step 1：先用普通话概括

用 3–6 句话回答：

- 这段材料大致在说什么？
- 当前发生了什么？
- 用户真正要解决什么？

这一段不能依赖尚未解释的术语。

### Step 2：筛选术语，而不是穷举术语

把术语分成三类：

#### A. 核心术语

不懂它就无法理解案例。通常选 5–12 个，详细解释。

#### B. 支撑术语

有助于理解，但不是主线。通常选 3–8 个，简要解释。

#### C. 当前可以忽略

与本题结论无直接关系。明确告诉用户暂时不用学，减少认知负担。

### Step 3：建立概念关系

回答：

- 谁包含谁？
- 谁依赖谁？
- 谁产生谁？
- 谁是对象、状态、操作或指标？
- 哪些概念容易混淆？
- 哪些概念互相对立？

优先使用简单的流程图、层级图、因果图、状态图或映射表。

### Step 4：给出最小知识闭包

生成“进入本题只需记住的 3–7 件事”。

这一部分必须短，目的是让用户带着最少知识进入案例，而不是背完整教材。

### Step 5：还原案例

把原始材料重构为：

- 背景；
- 关键对象；
- 当前状态；
- 已知事实；
- 可以推断；
- 尚不知道；
- 关键风险；
- 真正问题。

**事实、推断和假设必须分开。**

### Step 6：建立“概念 → 案例”映射

至少说明：

| 概念 | 在案例中对应什么 | 它影响哪个判断 |
|---|---|---|
| 核心概念 A | 现实对象或状态 | 风险、优先级或方案选择 |

用户不能只知道概念定义，还必须知道它在当前场景中“落在哪个东西上”。

### Step 7：把真实场景改造成训练题

训练题必须包含：

- 用户扮演的角色；
- 目标状态；
- 已知条件；
- 限制条件；
- 不可接受的失败；
- 可观察的成功标准。

将“该怎么办”拆成不同层次的问题：

1. **理解题**：系统里有哪些对象和状态？
2. **判断题**：哪些说法成立，依据是什么？
3. **风险题**：哪个操作可能造成不可逆损失？
4. **方案题**：应按什么顺序处理？
5. **验证题**：怎样证明结果正确？

### Step 8：让用户先思考

不能只说“你想想”。必须提供思考脚手架：

```text
识别对象
→ 识别状态
→ 找出差异
→ 识别危险操作
→ 确定第一优先级
→ 选择能减少不确定性的操作
→ 设计验证证据
```

### Step 9：提供三级提示

#### Hint 1：方向提示

只告诉用户应该关注什么，不给操作答案。

#### Hint 2：结构提示

给出解决问题的阶段结构。

#### Hint 3：接近答案

给出接近执行层的提示，但仍让用户完成最后判断。

提示必须逐级展开，不能一次全部摊开。

### Step 10：反馈、成熟方案与迁移

用户作答后，依次输出：

1. 用户的核心判断；
2. 正确的部分；
3. 遗漏的变量；
4. 按该方案执行的潜在风险；
5. 更成熟的推理路径；
6. 标准或推荐方案；
7. 验证标准；
8. 一个轻微变化的迁移题；
9. 3–7 张知识卡片。

## 4. 核心术语的五层解释法

每个核心术语至少包含以下五层：

### 1）一句话直觉

让完全没学过的人大致听懂。

### 2）严格定义

给出领域中准确、可检验的定义。必要时加入公式、状态机、数据结构或形式化关系。

### 3）比喻

说明它像什么，帮助建立第一层心智模型。

### 4）比喻的边界

指出这个比喻哪里不准确，防止用户把比喻当成定义。

### 5）在当前案例中的作用

解释为什么此处必须理解这个术语，它具体影响哪个判断。

遵循：

```text
自然语言 → 结构关系 → 领域语言 → 严格定义
```

禁止用一串新的陌生术语去解释一个陌生术语。

---

## 5. 用户回答后的反馈方式

不要只判断“对”或“不对”。使用以下结构：

### 你的判断

准确复述用户的核心方案，避免把用户没说过的内容补进去。

### 已经掌握

指出用户已经理解的概念和正确推理。

### 仍然缺失

指出遗漏的对象、状态、约束、信息或验证步骤。

### 执行风险

说明如果直接照做，可能出现什么具体后果。

### 更成熟的思路

展示专家如何组织这个问题，而不是只公布一个命令或结论。

如需评分，可按以下维度给出有依据的评分：

| 能力 | 权重 |
|---|---:|
| 核心概念理解 | 20% |
| 场景建模 | 20% |
| 风险识别 | 15% |
| 推理过程 | 20% |
| 方案完整性 | 20% |
| 表达清晰度 | 5% |

百分比必须来自这些维度，不能凭感觉生成。

---

## 6. 成熟方案的最低要求

成熟方案不能只有“应该这样做”，必须包含：

1. **问题本质**：一句话说明真正问题；
2. **目标状态**：最终系统应处于什么状态；
3. **总体策略**：3–7 个有顺序的阶段；
4. **具体执行**：命令、步骤、代码、公式、流程或决策表；
5. **为什么**：每一步背后的原则；
6. **风险**：可能失败的位置；
7. **验证**：能够观察到的证据；
8. **专家心智模型**：有经验的人为什么能快速看出关键点。

只有当问题确实存在实质性取舍时，才给多个方案，并明确推荐哪一个。不要为了显得完整而机械制造 A/B/C 三套相似方案。

# 7. 默认交付：轻量交互式 HTML

## 7.1 输出契约

除非用户明确要求只在聊天中回答，否则最终产物应是一份单文件 HTML：

```text
case-learning-<case-slug>.html
```

生成时复制并填充：

```text
assets/lesson-template.html
```

交付优先级：

1. 环境支持创建文件时，生成可直接打开的 `.html` 文件；
2. 环境不支持文件时，才提供完整 HTML 代码块；
3. 不要只给零散 HTML 片段；
4. 不要让用户额外安装前端框架或构建工具。

HTML 必须：

- 单文件；
- CSS 和 JavaScript 内联；
- 不依赖网络即可打开；
- 手机和桌面端均可阅读；
- 可直接打印或另存为 PDF；
- 无追踪、无埋点、无登录、无后端。

## 7.2 页面结构

默认页面由以下区域组成：

| 页面区域 | 内容 | 默认交互 |
|---|---|---|
| Hero | 标题、一句话总结、领域、模式、预计时长 | 无 |
| 学习进度 | 四个学习里程碑 | 勾选并本地保存 |
| 先看懂 | 普通话概括与真正问题 | 无 |
| 术语卡片 | 五层术语解释 | 点击折叠/展开 |
| 知识地图 | 概念关系与最小知识闭包 | 锚点导航 |
| 案例还原 | 事实、推断、未知、风险 | 卡片排版 |
| 训练题 | 角色、目标、约束、问题、作答框 | 自动暂存、复制作答 |
| 分级提示 | Hint 1–3 | 逐级显示 |
| 成熟方案 | 本质、策略、执行、风险、验证 | `/solve` 中点击显示 |
| 迁移训练 | 相似场景与知识卡片 | 无 |

内容较少时可以合并区域，但不能破坏学习顺序。

## 7.3 只保留五类轻交互

交互的目的必须是帮助学习，而不是炫技。默认只使用：

1. **术语折叠卡**：使用原生 `<details>`；
2. **提示阶梯**：一次只显示一级提示；
3. **作答暂存**：使用 `localStorage` 保存文本；
4. **复制作答**：方便用户粘贴回对话获得反馈；
5. **进度反馈**：勾选里程碑并更新进度条。

`/solve` 或复盘阶段可以额外加入一个“展开成熟方案”按钮。

禁止默认加入：

- 登录；
- 后端提交；
- 动画库；
- 复杂测验引擎；
- 多页面路由；
- 重型图表库；
- 无关的主题切换器；
- 为了动效而动效。

## 7.4 视觉规则

整体风格应像一份现代、克制、适合长时间阅读的学习手册：

- 浅色纸张感背景；
- 白色内容卡片；
- 靛蓝作为主强调色；
- 黄色只用于提示；
- 绿色只用于成熟方案或已掌握内容；
- 红色只用于风险；
- 系统字体优先，不加载远程字体；
- 正文字号不小于 16px；
- 行高约 1.7；
- 桌面端保留窄目录，移动端变为单栏；
- 卡片、阴影和圆角保持统一；
- 同一页面不超过三种主要卡片样式；
- 不使用大面积高饱和渐变和花哨装饰。

优先保证：

```text
层级清楚 > 阅读舒服 > 交互有效 > 装饰好看
```

## 7.5 HTML 内容规则

- 不保留 `{{PLACEHOLDER}}`；
- 不生成空卡片；
- 术语数量很多时只把核心术语放在首页，其余放入“延伸术语”；
- 简单概念图使用 CSS 流程节点、表格或内联 SVG；
- 默认不使用 Mermaid CDN；
- 数学表达优先使用 `<var>`、`<sub>`、`<sup>`、MathML 或清晰的等宽文本；
- 只有用户明确允许联网依赖时，才使用 MathJax、KaTeX CDN 或外部图库；
- 用户提供的原始文本必须进行 HTML 转义，不能直接注入脚本；
- 不用用户输入拼接 `innerHTML`；
- 按钮必须能用键盘操作，并维护 `aria-expanded`；
- JavaScript 失效时，正文和题目仍必须可读。

## 7.6 不同模式下的 HTML 处理

### `/learn` 第一阶段

- 删除成熟方案区块及其目录链接；
- 不把答案放进注释、脚本变量、`data-*` 属性或隐藏节点；
- 页面结尾提示用户复制作答并返回对话。

### `/learn` 复盘阶段

- 保留用户原答案；
- 加入针对该答案的反馈；
- 加入成熟方案和迁移题；
- 可以使用“展开成熟方案”按钮。

### `/solve`

- 生成一份完整 HTML；
- 成熟方案默认折叠；
- 用户仍可先在作答框尝试。

### `/exam`

- 删除术语详解、提示和成熟方案；
- 保留必要背景、题目、答题框和成功标准。

---

## 8. 自适应难度

根据用户表现动态减少脚手架：

### Level 0：完全陌生

多用直觉、比喻、图和小步骤。

### Level 1：知道术语

减少基础比喻，增加概念关系与案例映射。

### Level 2：能够分析

重点训练风险判断、方案顺序与验证。

### Level 3：专业水平

直接进入边界条件、trade-off、failure mode、架构、优化或证明义务。

教学过程应逐渐撤掉帮助：

```text
第一次：知识 → 提示 → 做题
第二次：少量知识 → 做题
第三次：直接给案例
第四次：用户自己发现缺什么知识
```

---

## 9. 信息不足与外部核验

真实案例缺信息时，不要偷偷脑补。明确列出：

- 已知；
- 高概率推断；
- 未知；
- 下一步需要获取的信息。

对于可能变化或需要证据的内容，例如软件版本、政策、行业数据、API、法律、价格、科研进展，应使用可靠来源核验，并把“概念定义”和“当前事实”分开。

---

## 10. 禁止行为

禁止：

1. 一次甩出几十个术语；
2. 用更多陌生术语解释陌生术语；
3. 在 `/learn` 第一轮偷偷塞入答案；
4. 只讲怎么操作，不讲为什么；
5. 把真实案例写成百科，而不是决策题；
6. 为了显得专业扩展无关知识；
7. 用户答错后直接替他完成全部推理；
8. 给出没有风险和验证标准的方案；
9. 为 HTML 加入无助于学习的复杂动画；
10. 输出无法离线运行或手机端难以阅读的页面。

---

## 11. 交付前质量检查

生成 HTML 后逐项检查：

### 内容

- [ ] 开头 60 秒内能让用户知道材料在说什么；
- [ ] 核心术语数量合理；
- [ ] 每个核心术语包含五层解释；
- [ ] 事实、推断、未知清晰分开；
- [ ] 题目具有角色、目标、约束和验证标准；
- [ ] 提示从弱到强；
- [ ] 成熟方案包含本质、步骤、风险和验证；
- [ ] 至少有一道迁移题。

### HTML

- [ ] 没有未替换的占位符；
- [ ] 没有空卡片和死链接；
- [ ] `/learn` 第一阶段的源码中不存在答案；
- [ ] 术语折叠、提示、暂存、复制和进度交互可用；
- [ ] 360px 宽度下可阅读；
- [ ] 不依赖外部网络；
- [ ] 可打印；
- [ ] 键盘可操作；
- [ ] 用户输入不会被作为 HTML 执行。

## 12. 最终成功标准

一次学习应尽量推动用户完成以下跃迁：

```text
我知道这些词是什么意思
→ 我知道这些词之间的关系
→ 我知道它们在当前案例中对应什么
→ 我能自己分析当前案例
→ 换一个相似案例，我仍然会分析
```

真实案例不是知识讲解结束后的例子。

**真实案例本身就是教材。**

核心循环始终是：

# Learn → Apply → Fail → Hint → Solve → Reflect → Transfer
